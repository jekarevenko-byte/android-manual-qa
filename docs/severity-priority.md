# Severity и Priority

**Severity** — насколько дефект ломает продукт (определяет тестировщик).
**Priority** — как срочно чинить (определяет команда с учётом бизнеса).

| Severity | Признак | Пример |
|---|---|---|
| Blocker | приложение не запускается или падает, нельзя пройти основной сценарий | краш при старте |
| Critical | основная функция не работает, нет обхода, данные теряются | созданная запись пропадает после перезапуска |
| Major | функция работает неверно, есть обходной путь | кнопка «Назад» ведёт не на тот экран |
| Minor | небольшая функциональная неточность | неверный порядок сортировки при равных значениях |
| Trivial | косметика | опечатка, смещение иконки на 2 px |

Priority: **High** — чинить в текущем релизе; **Medium** — в ближайших; **Low** — при случае.
Пример разницы: опечатка в названии компании на главном экране — Severity Trivial, но Priority High.
